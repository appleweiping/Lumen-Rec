\section{Prompts}\label{app:prompts}
All prompts are single-turn chat messages with thinking disabled; the answer is the first generated token, read as \texttt{Yes}
or \texttt{No} by token id from the top-50 log-probabilities. \textbf{V0}, the registered prompt of the rated panels (user
message, no system message):
\begin{quote}\ttfamily\scriptsize\raggedright
You are an expert recommendation system.\\[1pt]
User history (oldest to newest):\\
- \{title\} (rated \{r\}/5) \quad[last 10 events, one line each]\\[1pt]
Candidate item:\\
Title: \{title\}\\
Description: \{first 200 characters, if present\}\\[1pt]
Would this user like the candidate item? Answer with only Yes or No.
\end{quote}
Next-item panels use the same template with plain history lines (``- \{title\}'', last 5 events) and the question
\textsf{next} (``Will this user purchase the candidate item next?'') or \textsf{like}; their prompt stays frozen at V0. The like
family adds ``Would this user dislike the candidate item?'' and the paraphrases ``Is the candidate item a good match for
this user's taste?'' and ``Would this user be disappointed by the candidate item?''. The threshold family (V1, V7) asks ``Will this
user rate the candidate item 4 stars or higher (on a 1-5 scale)?'' (like), with parallel star-threshold wording for the other three.
All of these were fixed in advance and are scored only after the zero-shot gate is passed. Table~\ref{tab:app-bank} lists the seven
registered variants.

\section{Registered Amendments}\label{app:prereg}
Each item below was written before the data it governs were generated; the registration is a timestamped project document, not an
entry in a public registry. \textbf{Amendment 1} (before any pilot data): fp16 scoring; \texttt{Yes}/\texttt{No} read by token id with
censoring flags; every interval resamples the independent unit; tie-aware ranks; first event per (user, item) on rated panels;
byte-identical rebuild of the next-item panels; global temporal split at the 0.8 quantile of candidate timestamps. \textbf{Amendment 2}
(after the pilot gate result, before further GPU jobs): the remedy round (invariants, seven-variant bank, development and confirmation
users disjoint by id, selection blind to the two-view arm, one confirmatory gate, stage-3 arms only after a pass, contingency for
failure, a decision-table hole closed as ``indeterminate''); Gate-FT (LoRA, three seeds, trained on development-user candidates before
$T$, evaluated on confirmation-user candidates at or after $T$, pass iff the mean UAUC is at least 0.65 and every run passes the
integrity checks); the next-item audit (zero-shot scoring under V0 before the freeze, analysis plan fixed in advance, sports events
1--1000 quarantined); the diagnosis battery (interpretive only) and CPU artifact checks (exploratory, three wording-only rules); and the
forking-path rules (immutable constants 0.60, 0.1863 and 0.65; one prompt round; fixed unit roles; no promoted arm; reference rows in
every rated table; claim admission; $2\sigma_{\rm seed}$ rule; retirement rule of the nested method slot; banned claims).
\textbf{Amendment 3} (before any fine-tuned adapter existed; revised before any outcome statistic of one): the fine-tuned program,
conditional on a recorded Gate-FT pass except for its zero-shot panels: data roles (the first 1,500 users of each rated domain train,
the next up to 3,000 evaluate, split at the 0.8 quantile $T_d$ into CAL and TEST), the endpoint dictionary with the single primary
hypothesis P1, the zero-shot panels (rated, and a Llama next-item replication on events 1,001--3,000), the per-model knockout labels,
pruning arms with removal within each label class, the nested method slot with its kill rule, a Llama replication on ML-1M and Toys, a
within-item label-permutation control, the Holm families, and cut rules announced before any result.

\section{Diagnosis Battery}\label{app:battery}
The battery ran on burned users (Qwen3-8B, fp16) after the freeze. Its readings are interpretive only and cannot change any gate, bank,
split or contingency; the star-permutation reading is re-tested on evaluation users in Table~\ref{tab:decomp}. It adds four strings: a
no-user probe (``Movie: \{title\} \ldots{} Is this movie widely considered good?''), a positive control that appends ``(This user later
rated this item r/5.)'', an evidence injection that appends ``Average rating by other users before this date: m/5 (n ratings)'', and a
digit readout (``What star rating from 1 to 5 would this user give the candidate item?'', answered by one digit).

\section{Pseudonym Knockout Protocol}\label{app:pseudonym}
The knockout is a test-time intervention on fixed models (adapters are not retrained on pseudonyms). It runs on Amazon Toys and Video
Games for Qwen3-8B (zero-shot and LoRA seeds 0--2), on Toys for Llama-3.1-8B-Instruct, and on Sports for Qwen3-8B unless cut. A
single-pass, whole-word, case-insensitive substitution replaces every \texttt{store} string in the history and the candidate text by a
pseudonym; a stop-list excludes generic or placeholder stores and strings shorter than four characters or made of digits. Pseudonyms are
injective within a panel and never equal a real store string. The placebo maps every brand that the pseudonym arm maps, history-only
brands included, to another real brand of the same tercile of category-wide brand review counts, with identical substituted key sets.
Treated candidates are those whose store string occurs as a whole word in their own title (their share is reported); brand tokens beyond
the store field are not substituted. Intervals are user-cluster bootstraps; UAUC is computed over all candidates (primary) and over
treated candidates. The label of each model follows the registered rule of Section~\ref{sec:exp-rq5}; NULL means that pseudonymisation
destroys evidence in that domain (a UAUC fall of more than 0.02 overall and in the tail). Table~\ref{tab:app-ko} lists every model.

\section{Reproducibility Checklist}\label{app:repro}
\begin{itemize}\setlength{\itemsep}{0pt}\setlength{\parsep}{0pt}\setlength{\topsep}{2pt}
\item \emph{Models and scoring.} Qwen3-8B~\citep{yang2025qwen3} and Llama-3.1-8B-Instruct~\citep{grattafiori2024llama3}; chat template,
  thinking off; prefill-only fp16 scoring with vLLM~\citep{kwon2023vllm}; \texttt{Yes}/\texttt{No} read by token id from the top-50
  log-probabilities; at most 4,096 tokens (3,072 in the next-item audit); 100-user chunks.
\item \emph{Fine-tuning.} LoRA~\citep{hu2022lora} on the query, key, value and output projections, $r{=}16$, $\alpha{=}32$, dropout 0.05,
  learning rate $10^{-4}$, cosine decay, 3\% warm-up, one epoch, bf16, batch 8 $\times$ 4; at most 24,000 training examples per domain;
  prompts above 1,024 tokens skipped and counted (a domain with more than 2\% such prompts trains with the 99.5th-percentile length
  rounded up to 256); seeds 0, 1, 2 (pruning: five seeds; permutation control: seeds 0 and 1); every seed is reported, and a run that
  fails its integrity checks twice is reported as missing.
\item \emph{Statistics.} Percentile bootstrap, 2,000 resamples, seed 0, over users or events; tie-aware ranks; Holm correction within the
  registered families; P1 and the pruning contrast are single tests at 0.05; a fine-tuned gain needs $2\sigma_{\rm seed}$ with all seeds
  agreeing in sign.
\item \emph{Data and hashes.} Training users are the first 1,500 users of each rated domain in seed-0 row order and evaluation users the
  next ones (at most 3,000), disjoint by id. Pilot ML-1M panel 985494c7, pilot Toys panel 69252b48, registered V0 prompts on the pilot
  ML-1M panel 12e83c4f (first eight hexadecimal digits of the sha1); \DATANEEDED{amendment sha1s, rendered prompt-bank sha1, user-id list
  sha1s and the time split $T_d$ of every domain from the freeze record and ftgrid\_split.json}.
\item \emph{Software, compute, artifact.} \DATANEEDED{package versions and GPU model from each report.json; total GPU hours}. Prompts, panel
  builders, scorers, analysis scripts and every result file are released with the anonymous artifact; every number in the paper is read
  from a committed result file.
\end{itemize}
